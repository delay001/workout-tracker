# План: приложение в виде APK для Android

Статус (2026-11-04): шаги 1–3, 5–6 сделаны: отдельная сборка, проект Android (Capacitor 8), экспорт и импорт
через «Документы» и «Поделиться», ключ подписи (лежит у пользователя в «Документы/workout-tracker-key»,
в git его нет), сценарий .github/workflows/apk.yml. Дальше: секреты в GitHub, проверка на телефоне, шаги 4, 7, 8.

## Выбранный способ: Capacitor

Готовое приложение кладется внутрь apk, его показывает системный WebView Android. Код почти не меняется,
данные хранятся в самом приложении и не зависят от Chrome.

| Способ | Как работает | Где данные | Решение |
|---|---|---|---|
| TWA (PWABuilder, Bubblewrap) | apk — ярлык на сайт GitHub Pages, внутри Chrome | В Chrome, как сейчас: очистка данных Chrome стирает все | Нет: надежность не растет |
| **Capacitor** | Сайт целиком внутри apk, работает без интернета | В песочнице приложения: пропадают только при удалении приложения или «Очистить данные» | **Да** |
| Переписать на Kotlin или Flutter | Новое приложение | Как угодно | Нет: дорого, все заново |

## Шаги

1. **Отдельная сборка для apk.** `npm run build:apk`: относительные пути, без service worker (в apk он не нужен).
   Сайт на GitHub Pages продолжает работать как раньше.
2. **Capacitor и проект Android.** Название «Трекер тренировок», иконка, темная заставка, только вертикальная ориентация.
3. **Экспорт и импорт.** Скачивание файла через браузер в apk не работает:
   - экспорт сохраняет JSON в «Документы» и открывает системное «Поделиться» (Telegram, Google Диск, почта);
   - импорт через выбор файла, как сейчас;
   - формат файла тот же, старые копии подходят.
4. **Защита данных в три уровня.**
   - Основная база — IndexedDB внутри приложения, код хранения не меняется.
   - Встроенная резервная копия Android (Auto Backup): раз в сутки данные приложения уходят в Google Диск,
     при переустановке на том же аккаунте возвращаются.
   - Автокопия файлом: после каждой тренировки перезаписывается один файл `workout-backup.json` в «Документах»
     (в apk это возможно, в PWA файлы копились бы в «Загрузках»).
5. **Ключ подписи — самое важное.** Обновление ставится поверх старой версии, только если подписано тем же ключом.
   Потеря ключа = новую версию можно поставить только после удаления старой, то есть с потерей данных.
   Хранить ключ в секретах GitHub и в резервном месте у пользователя.
6. **Сборка на GitHub.** Android Studio ставить не нужно: при новой версии GitHub прогоняет тесты, собирает
   подписанный apk и выкладывает в «Релизы». Пользователь скачивает файл и ставит поверх, данные сохраняются.
7. **Перенос данных из PWA (один раз).** Экспорт в PWA → установка apk → импорт в apk.
   PWA пока не удалять, оставить запасным вариантом.
8. **Проверка, что ничего не сломалось.**
   - Автоматически на каждую сборку: все тесты плюс расширенные сценарные тесты экранов
     (история, правка тренировки, импорт и экспорт).
   - Вручную на телефоне по списку (~15 пунктов): тренировка от начала до конца, «Отменить», перетаскивание,
     секундомер, вибрация; экспорт → удаление → установка → импорт; режим полета; данные после перезагрузки
     телефона; данные после установки новой версии поверх старой.

## Порядок

1. Шаги 1–3 и 5–6: первый apk, который можно поставить и потрогать.

## Открытые вопросы к пользователю

1. Apk только для себя, без Google Play? (Исходим из этого. Play — аккаунт разработчика $25,
   политика конфиденциальности, проверка Google.)
2. Нужна автокопия в «Документы» после каждой тренировки (шаг 4)?
3. Включать встроенную копию Android в Google Диск (данные будут лежать в аккаунте Google)?
