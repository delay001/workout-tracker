# Выпуск apk

Apk собирает GitHub (`.github/workflows/apk.yml`), подписывая ключом из секретов. Локально Android SDK нет — ничего не собирать на компьютере.

## Шаги

1. Проверить, что все готово:
   - `npx.cmd tsc --noEmit` и `npx.cmd vitest run` — без ошибок;
   - `npm.cmd run build:apk` — собирается (код только для apk лежит за `import.meta.env.MODE === 'apk'`).
   - Если менялись плагины Capacitor или `capacitor.config.ts`: `npx.cmd cap sync android` и закоммитить изменившиеся `android/*.gradle`.
2. Закоммитить на русском и отправить: `git push origin main` (при сбое сети повторить через 15–20 с).
3. Запустить сборку тегом: `git tag apk-<суть-правки>` и `git push origin apk-<суть-правки>`.
   Номер версии = номер запуска сценария (1.0.N); тег — только для запуска и имени релиза.
4. Ждать в фоне ~4–5 минут (`sleep 270` с `run_in_background`), не опрашивать API GitHub без авторизации — он быстро упирается в лимит.
5. Проверить файл без API:
   `curl -sI -L "https://github.com/delay001/workout-tracker/releases/download/<тег>/workout-tracker-1.0.<N>.apk"` → в ответе есть `Content-Type: application/vnd.android.package-archive` и размер ~3 МБ.
   Строке `HTTP/1.1 200` не верить: сетевой прокси отвечает «200 Connection established» и на несуществующий файл.
   Номер N не угадывать: если файла нет, открыть страницу Actions «Сборка APK» в браузере и посмотреть номер последнего запуска и его статус.
6. Дать пользователю прямую ссылку на apk, коротко: что вошло в версию, «ставится поверх, данные сохраняются», что проверить на телефоне.

## Если сборка упала

Открыть запуск на странице Actions, найти шаг с ошибкой, исправить, повторить с новым тегом. Не удалять старые теги и релизы без просьбы пользователя.

## Нельзя

- Менять ключ подписи и секреты GitHub: ключ лежит у пользователя (`Документы/workout-tracker-key`), без него обновить приложение поверх нельзя.
- Собирать apk без ведома пользователя, если он сказал «apk пока не надо».
